## 1. The TA: one assistant for every project on the site

1. Yes: I'd keep one TA, with one kernel, one set of rules and one examination, but it reads only what each question needs. On a net's guide page it reads that net's pack; on the lab page you choose one net or every net.

2. **Why one TA.**
   a. The nets share parts (attention, the diagram editor, the publish tool and our own code), so questions often cross projects.
   b. One kernel means one deployment and one pass key.
   c. A new project joins simply by being published with a guide.

3. **The limit.** "Every net" is about 151,000 characters today, which fits comfortably, but it grows with each project. When it gets too big, I'd add a choice per project, and later have the TA read only the sections relevant to the question, rather than split it into several TAs.

4. **The alternative** is a separate TA for each project, with its own rules and examination. That's only worth it if a project needs a different audience or different house rules.
